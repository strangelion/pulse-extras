# Architecture / 架构

Zig-first, fixed stable toolchain, Windows x64 MSVC ABI. No Cargo or C++ build pipeline in the active project. The official SDK exposes a C ABI but documents C++ authoring; Zig-built ABI Probe and Hello Panel have recorded isolated host acceptance; each new extension and registry submission require their own evidence. Never link private Pulse internals.

## Boundaries

- shared/pulse/raw: bindings generated by `scripts/generate_bindings.py` (`zig translate-c` over the pinned headers), never edited by hand.
- shared/pulse: safe wrappers over the raw bindings — `abi` (status codes, string views), `host` (table held by value, validated queries), `context`, `commands`, `ui_model`, `ui_mount`, `text` (UTF-8-safe copying).
- shared/diagnostics: opt-in file logger used by acceptance runs; no telemetry, no environment dumps.
- shared/process: initial structured-argv runner with timeout and output caps; cancellation, process-tree ownership and DLL-safe runtime teardown are outstanding.
- shared/vcs: implemented provider contract, capabilities, identities, detection, risk tiers, CLI discovery, bounded cache and Git/JJ/SVN read-only summaries. Full identity resolution, cache isolation and asynchronous panel integration are outstanding. See [vcs-architecture.md](vcs-architecture.md).
- extensions/abi-probe: lifecycle probe used to verify entry/activate/deactivate/destroy on a real host.
- extensions/hello-panel: first UI extension — command, `pulse.context` subscription, `pulse.ui.model` panel, `pulse.ui.mount` workspace/sidebar placement.
- Future independent extensions: Convert, Inspect, Data, DevKit, Compare and Forge. Heavy parsing, external commands and untrusted input should use isolated workers where practical. [Forge](forge-architecture.md) is a separate proposed authoring CLI/MCP and optional native panel; untrusted generated code requires OS-enforced containment, not just a separate Pulse profile. Direct integration into the built-in AI requires an upstream public interface.

## Safety

Use explicit allocation ownership, bounded resources, clear error unions and cleanup. Never free host-owned memory, retain borrowed callback data, or cross ABI with unwinding. Zig safety checks can still terminate a process; they are not a sandbox or a substitute for worker isolation. Use ReleaseSafe for production DLLs unless evidence supports another mode. No unbounded I/O on UI threads. Respect the owner thread and drain callbacks/workers before unload. Never execute inspected binaries or interpolate shell commands. Do not upload user data or change files during passive browsing. Generated user files must use supported Pulse confirmation/staging; unsupported mutations remain disabled pending design review.

## Regression gates

1. Pin toolchain and SDK revision; run format checks, unit tests and Windows DLL builds.
2. Check C and Zig sizes, alignment, offsets, exports and calling convention. Test actual DLL loading through a C harness. Compare the pinned headers with a host's own header set mechanically (`scripts/verify_abi_prefix.py`) and record which headers the host did not ship.
3. Test allocation failure, cancellation, stale callbacks, unload and malformed inputs when relevant; use std.testing.allocator in owned logic.
4. Validate real Pulse install, enable, restart, upgrade and rollback in isolated profiles. A C harness is not real host acceptance.
5. Track cold/warm build time, cache and output size, runtime memory and UI responsiveness. Establish baselines before setting thresholds; no claims without measurements.

Use no private signing keys in Git or logs. Independent packages under strangelion.*; preserve Apache-2.0, audit third-party licenses, sign official manifest bytes, publish releases and submit catalog metadata to the upstream registry. See [release design](release.md) for the proposed shared packaging pipeline, independent versions, selection and protected signing. No release workflow exists yet.

## Development discipline

Use the pinned Zig version's installed standard library and compile each API change before pushing. Preserve the existing probes, generated-binding workflow and passing checks. Do not add Rust/Cargo, AGENTS.md, private SDK dependencies or placeholder providers. Follow the scope-specific gates in [testing.md](testing.md); manually run full CI before release or after a sequence of reduced checks. A skipped check is not evidence of passing it.
